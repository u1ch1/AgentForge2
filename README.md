# AgentForge Studio

Десктопное приложение (Electron + React + TypeScript) — рабочее место для команды
из четырёх AI-агентов. Агенты ходят в два провайдера: **Anthropic (Claude)** и
**Moonshot (Kimi)**. Дешёвые модели для рутины, дорогие — для сложного, с учётом
расходов и лимитом бюджета.

Работа ведётся по проектам: **проект = папка на диске = свои задачи, своя
память и отдельный диалог с каждым агентом**. Проекты переключаются вкладками
сверху, как карточки в CRM.

Интерфейс сделан в духе тёмной темы Adobe Photoshop: своя строка заголовка
вместо системной рамки Windows, строка параметров, вертикальные рейки
инструментов и панелей, строка состояния. Иконки — штриховые SVG, эмодзи
в интерфейсе не используются.

Внутри: чат со стримингом, автоматический конвейер «задача → готовый проект»
(Analyst → Admin → воркеры → Tester/Designer), редактор системных промптов,
дерево задач с Auto-Fix, файловый доступ к проекту, живой браузер для
предпросмотра и ручных проверок, память проекта, генератор
Docker/Railway/Vercel-конфигов и экспорт в ZIP.

## 1. Что нужно установить

| Программа | Версия | Ссылка |
|---|---|---|
| **Node.js** | 20 LTS или новее | https://nodejs.org/ |
| Git | любая (необязательно) | https://git-scm.com/download/win |

Проверка в PowerShell:

```bash
node -v
```

Должно быть `v20.x` или выше. Больше ничего ставить не нужно.

**API-ключи** (нужен хотя бы один):
- Anthropic — https://console.anthropic.com/ → API Keys
- Moonshot — https://platform.moonshot.ai/ (или `platform.moonshot.cn` для Китая)

Из корня проекта (`D:\AgentForge`):

```bash
npm install
```

```bash
npm run build
```

## 3. Запуск

```bash
npm start
```

`npm start` пересобирает проект и запускает приложение. Если код не менялся,
можно быстрее:

```bash
npx electron .
```

Режим разработчика (с DevTools):

```bash
npm run dev
```

Проверить типы без сборки:

```bash
npm run typecheck
```

```bash
powershell -ExecutionPolicy Bypass -File scripts\create-shortcut.ps1
```

Скрипт сам определит, что запускать: собранный EXE (если делали `npm run dist`)
или `electron.exe` из `node_modules` — **без чёрного окна консоли**.

> Ярлык на `electron.exe` не пересобирает проект. После правок в коде выполните

```
┌──────────────────────────────────────────────────────────────────┐
│ ▣ Файл Правка Проект Агент Вид Справка   Проект — AF   – □ ✕     │ строка заголовка
├──────────────────────────────────────────────────────────────────┤

├──────────────────────────────────────────────────────────────────┤
│ ◎ Admin · Координатор · Модель: [Claude Opus 5 ▾] · Anthropic    │ строка параметров
├────┬───────────────┬──────────────────────┬───────────────┬──────┤
│ и  │               │                      │               │  п   │
│ н  │  левая панель │        чат           │ правая панель │  а   │
│ с  │               │      («холст»)       │               │  н   │
│ т  │               │                      │               │  е   │
│ р  │               │                      │               │  л   │
├────┴───────────────┴──────────────────────┴───────────────┴──────┤
│ Готово │ Проект │ модель │ 12 сообщ. │ $0.02/$10 │ путь к папке  │ строка состояния
└──────────────────────────────────────────────────────────────────┘
```

Системной рамки Windows нет — сверху ровно одна полоса, наша. За неё окно
перетаскивается, двойной щелчок разворачивает, справа кнопки свернуть,
развернуть и закрыть.

**Вкладки проектов** — переключение проекта меняет сразу всё: папку, задачи,
память и переписку со всеми агентами. Двойной щелчок по вкладке переименовывает
проект, «+» создаёт новый, «✕» убирает из списка (файлы на диске остаются).
Цифра на вкладке — сколько всего сообщений в проекте.

**Строка параметров** — активный агент, его модель, провайдер, индикатор ключа
и кнопка прерывания генерации.

**Левая рейка — инструменты:**

| Значок | Инструмент | Что показывает |
|---|---|---|
| перекрестье со стрелками | Агенты | агенты проекта; цифра — сообщений в диалоге |
| дерево узлов | Задачи | задачи и подзадачи текущего проекта |
| фигуры | Шаблоны | каркасы проектов |
| пластырь | Auto-Fix | подзадачи, ждущие исправления |

**Правая рейка — панели:**

| Значок | Панель | Что делает |
|---|---|---|
| папка | Файлы проекта | обзор папки, добавление файлов (кнопка или перетаскивание), создание папок, переименование, удаление, чтение, запись, поиск по коду |
| документ | Промпты агентов | редактор системных промптов из `.claude/` (общие для всех проектов) |
| столбики | Токены | расход по агентам: токены, стоимость, число запросов |
| глаз | Просмотр | живой браузер: dev-сервер поднимается сам при запуске приложения, показывает страницу и её консоль, кнопка «Прогнать проверки сейчас» — быстрый аудит без конвейера |
| микросхема | Память проекта | стек, компоненты, endpoint'ы, заметки — подмешиваются в промпт |
| стрелка вверх | Деплой | Dockerfile, docker-compose, nginx.conf, railway/vercel, GitHub Actions, экспорт ZIP |
| ползунки | Настройки | ключи, модели, бюджет, рабочая папка, эндпоинт Moonshot |

**Просмотр — живой браузер.** Это не окошко с картинкой, а встроенный
Chromium (`<webview>`) с собственной консолью.

- *Запускается сам.* При старте приложения dev-сервер активного проекта
  (`npm run dev`) поднимается автоматически — открыв «Просмотр», вы,
  скорее всего, сразу увидите готовую страницу. Если у проекта ещё нет
  `node_modules` или своего `package.json`, автозапуск молча не сработает —
  кнопка «Старт» осталась и покажет причину.
- *Консоль.* Ссылка «консоль (N)» под адресом страницы разворачивает
  реальные `console.log` и ошибки со страницы; уровень подсвечен цветом
  (красный — error, жёлтый — warning).
- *Прогнать проверки сейчас.* Кнопка внизу панели — отдельно от конвейера:
  поднимает проект командой `npm start`, стучится в него и снимает
  скриншот, без участия агентов и без расхода бюджета. Недоступна, пока
  конвейер занят тем же проектом.
- *Старт / Стоп / Перезагрузить* — ручное управление тем же сервером, если
  нужен другой путь (поле слева от кнопок, по умолчанию `.` — корень
  проекта).

**Чат** понимает разметку Markdown: заголовки, **жирный**, *курсив*,
~~зачёркнутый~~, `код`, блоки кода с подписью языка, списки, цитаты, таблицы,
ссылки. Текст выделяется мышью; у каждого сообщения и каждого блока кода есть
кнопка копирования.

Панели скрываются через меню **Вид**.

## 7. Первый запуск

1. Панель **Настройки** (правая рейка, нижний значок) открыта по умолчанию.
2. Вставьте ключ Anthropic и/или Moonshot, нажмите кнопку с ключом рядом с полем.
   Ключи шифруются средствами Windows (DPAPI) и переживают перезапуск.
3. Нажмите **Проверить ключ** — приложение запросит у провайдера список моделей
   и покажет, сколько их доступно. Это же подтверждает, что ключ рабочий.
4. Проверьте **Рабочую папку** (по умолчанию `Документы\AgentForge-Workspace`).
   Внутри неё в `projects/` лежат папки проектов.
5. Дайте проекту осмысленное имя: двойной щелчок по вкладке. Пока папка пуста,
   она переименуется вместе с проектом.
6. В блоке **Модели агентов** выберите модель каждому агенту.

Красная точка справа от агента означает «для его модели не задан ключ»,
зелёная — всё готово.

### Откуда берётся список моделей

Список **запрашивается у самих провайдеров** (`GET /v1/models` у Anthropic и
Moonshot), поэтому показывает ровно то, к чему у вашего ключа есть доступ —
включая новые модели, о которых приложение ничего не знает.

- Пока ключ не задан, показывается небольшой встроенный список.
- Кнопка **Обновить список моделей** (или меню **Проект → Обновить список
  моделей**) перезапрашивает его принудительно; между запросами он кэшируется
  на 10 минут.
- Смена ключа или эндпоинта Moonshot сбрасывает кэш автоматически.

Провайдер выбирается по имени модели: `claude-*` уходит в Anthropic, всё
остальное — в Moonshot. Разойтись эти два значения не могут.

> Цены заданы в `src/main/api-client.ts` (константа `PRICING`, доллары за
> **миллион** токенов). Для модели, которой там нет, берётся средняя цена её
> провайдера — расход считается приблизительно. Хотите точную бухгалтерию —
> допишите модель в таблицу.

## 8. Агенты и работа

| Агент | Роль |
|---|---|
| Analyst | первая линия: оценивает выполнимость задачи в процентах до начала работы |
| Admin | тимлид: анализ требований, выбор стека, декомпозиция |
| Worker1 | фронтенд: React, TypeScript, вёрстка, Telegram Mini Apps |
| Worker2 | бэкенд и DevOps: API, БД, Docker, CI/CD |
| Tester | QA и безопасность: тесты, аудит, отчёты |
| Designer | оформление: правит CSS и вёрстку по обмерам после воркеров |

Выберите агента слева и пишите в чат. `Enter` — отправить, `Shift+Enter` —
новая строка, **Стоп** — прервать генерацию.

### Типичный сценарий

1. **Вкладка «+»** → новый проект, например «Интернет-магазин». Создаётся папка
   `AgentForge-Workspace/projects/internet-magazin/`.
2. **Шаблоны** → «Node.js + React» — каркас создан внутри этой папки.
3. В созданных `frontend/` и `backend/` выполните `npm install` вручную
   (приложение чужие зависимости не ставит).
4. **Файлы проекта** → перетащите сюда макеты, ТЗ, примеры данных — всё ляжет
   в папку проекта, и агенты смогут это прочитать.
5. **Память проекта** → стек и заметки. Теперь агенты знают контекст.
6. **Admin** → опишите задачу, получите декомпозицию. Это отдельный диалог
   именно с Admin именно в этом проекте.
7. **Задачи** → занесите подзадачи, назначьте исполнителей. Щелчок по кружку
   статуса переключает `ожидает → в работе → готово`.
8. **Worker1 / Worker2** → у каждого свой диалог; просите код, переносите
   через **Файлы проекта**.
9. **Просмотр** → `frontend` → Старт — смотрите результат живьём.
10. **Tester** → аудит; найденное отправляйте в **Auto-Fix**.
11. **Деплой** → конфиги и ZIP.

Второй проект заводится вкладкой «+» и живёт полностью отдельно: своя папка,
свои задачи, своя переписка. Переключение — один щелчок по вкладке.

### Бюджет

Расход виден в строке состояния. При превышении лимита включается
**эконом-режим**: запросы уходят на самую дешёвую модель, выбор моделей
блокируется. Сбросить: **Настройки → Бюджет → Обнулить счётчик** (это обнуляет
накопленный расход, иначе эконом-режим включится снова сразу же).

## 9. Где что лежит

| Что | Где |
|---|---|
| Рабочая папка | `Документы\AgentForge-Workspace` — меняется в Настройках |
| Папки проектов | `<рабочая папка>\projects\<имя-латиницей>\` |
| Промпты агентов (общие) | `<рабочая папка>\.claude\agents\*.md` |
| Общие правила | `<рабочая папка>\.claude\rules\worker-rules.md` |
| Проекты, чаты, задачи, память, расход | `%APPDATA%\agentforge-studio\agentforge-data\*.json` |
| Зашифрованные API-ключи | `%APPDATA%\agentforge-studio\agentforge-data\api-keys.json` |

Имя папки проекта — транслитерация названия латиницей: папка становится рабочей
директорией для `npm` и контекстом сборки Docker, а кириллица и пробелы там
регулярно ломают сторонние инструменты. Фактический путь всегда виден в строке
состояния и в подсказке вкладки.

Убрать проект из списка — не то же самое, что удалить его: приложение забывает
о проекте, но папку и файлы не трогает. Удалять их нужно вручную.

Удалить всё состояние: закройте программу и удалите `%APPDATA%\agentforge-studio`.

## 11. Если что-то не работает

**«Не задан ключ …»** — панель Настройки, вставьте ключ, нажмите кнопку с ключом.

**Красная точка у агента** — для выбранной ему модели нет ключа. Введите ключ
или смените модель.

**«Ключ отклонён провайдером»** после «Проверить ключ» — ключ неверный либо
выдан на другой площадке. Для Moonshot проверьте эндпоинт: ключ с
`platform.moonshot.cn` не работает на `api.moonshot.ai` и наоборот
(Настройки → Эндпоинт Moonshot).

**В списке моделей мало пунктов** — значит показан встроенный список. Задайте
ключ и нажмите «Обновить список моделей».

**Просмотр не стартует** — нажмите «лог» под кнопкой. Частые причины: в папке
нет `node_modules` (выполните `npm install`), нет скрипта `dev` в
`package.json`, порт занят прошлым процессом.

**Ключи не сохраняются между запусками** — Windows не отдал шифрование. В
Настройках это написано прямо под полями ключей; тогда ключи живут только
в памяти.

**`npm install` ругается на уязвимости** — они в зависимостях `electron-builder`
(нужен только для `npm run dist`). На работу приложения не влияют.

## 12. Конвейер: от задачи до готового проекта

Помимо ручного чата с агентами есть автоматический режим — вкладка
**«Конвейер»** на левой рейке (первый значок, play). Вы описываете задачу
целиком, как заказчик, а дальше команда агентов доводит её до готового,
проверенного проекта сама — с двумя точками, где решаете вы.

1. **Analyst оценивает задачу.** Получает вашу формулировку первым и
   отвечает в процентах: вероятность довести задачу до рабочего результата
   и какую долю объёма конвейер закроет сам. Если формулировки не хватает
   для честной оценки, Analyst один раз может задать уточняющий вопрос —
   ответьте текстом, и оценка досчитается с учётом ответа.
2. **Вы решаете, делать или нет.** Окно с процентами и списком того, чего
   не хватает. «Делать» — задача уходит Admin. «Не делать» — прогон
   останавливается, воркеры не трогают ни строчки.
3. **Admin строит план** — список подзадач с исполнителями (Worker1 —
   фронтенд, Worker2 — бэкенд). Это вторая и последняя остановка: план
   можно поправить прямо в окне (порядок, текст, исполнитель) перед
   запуском.
4. **Дальше без остановок.** Воркеры пишут код и сохраняют его в файлы
   проекта, Tester прогоняет сборку и настоящий запуск приложения в
   браузере (тот же движок, что у панели «Просмотр», только без участия
   человека), Designer поправляет вёрстку по обмерам. Если что-то не
   сходится — код уходит на исправление автоматически, до трёх попыток.
5. **Журнал в реальном времени.** Панель конвейера показывает, что
   происходит прямо сейчас: шаги пользовательского сценария, который
   проигрывает Tester, появляются по мере выполнения, а не одной пачкой в
   конце; скриншот страницы обновляется по ходу проверки.

Готовый прогон можно посмотреть по вкладкам «Задачи» (тот же список
подзадач) и «Файлы проекта» (что записано на диск).
